# Большие вложения (chunked, до 10 ГБ)

Файлы грузятся кусками (chunked), поэтому **в один HTTP-запрос целиком не идут** —
сервер должен принимать лишь один чанк (`uploads.chunk_bytes`, по умолчанию 16 МБ),
а не весь файл. Это ключевой момент конфигурации.

## Поток

1. `POST /api/uploads` — init: проверка квоты/лимита/места, создаёт сессию и временный файл.
2. `PATCH /api/uploads/{id}` — чанк: тело = байты куска, заголовок `Upload-Offset: <смещение>`.
3. `POST /api/uploads/{id}/complete` — собирает файл, создаёт сообщение-вложение.
4. `GET /api/uploads/{id}` — принятый размер (для докачки после обрыва).

Большие файлы (> `uploads.encrypt_max_bytes`, 25 МБ) хранятся **без шифрования** и отдаются
потоком с диска с поддержкой Range. Маленькие — шифруются в памяти, как раньше.

## Развёртывание на проде

1. **Миграции** (новые таблицы `attachments`, `upload_sessions`):
   ```
   php artisan migrate
   ```

2. **nginx** — размер тела запроса должен покрывать ОДИН чанк (+запас), НЕ 10 ГБ:
   ```
   client_max_body_size 32m;
   # на location /api/uploads можно поднять таймауты, если канал медленный:
   proxy_read_timeout 300s;
   ```

3. **PHP** (`php.ini`) — тоже на размер чанка, не файла. По умолчанию `post_max_size`
   часто 8 МБ — это меньше чанка (16 МБ), чанки будут падать. Поднять:
   ```
   post_max_size = 32M
   upload_max_filesize = 32M   ; (на всякий случай; chunked читает raw body)
   ```
   Либо уменьшить `UPLOAD_CHUNK_BYTES` ниже текущего `post_max_size`.

4. **Планировщик** — ретеншн (`attachments:prune`, ежедневно в 04:00) работает только при
   живом cron Laravel:
   ```
   * * * * * cd /path/to/zovcord && php artisan schedule:run >> /dev/null 2>&1
   ```

5. **.env** — подгоните под размер диска VPS:
   ```
   UPLOAD_MAX_BYTES=10737418240        # 10 ГБ — потолок на файл
   UPLOAD_ENCRYPT_MAX_BYTES=26214400   # 25 МБ — порог шифрования
   UPLOAD_CHUNK_BYTES=16777216         # 16 МБ — размер чанка (<= post_max_size!)
   UPLOAD_USER_QUOTA_BYTES=21474836480 # 20 ГБ на пользователя
   UPLOAD_MIN_FREE_BYTES=5368709120    # держать 5 ГБ свободными (порог вытеснения)
   UPLOAD_RETENTION_DAYS=30            # срок хранения истории (0 — выкл)
   UPLOAD_SESSION_TTL_HOURS=24         # через сколько чистить брошенные загрузки
   ```

## Управление местом

- **Квота на пользователя** (`UPLOAD_USER_QUOTA_BYTES`): при превышении init вернёт 413.
- **LRU-вытеснение** (`UPLOAD_MIN_FREE_BYTES`): если после приёма файла на диске останется
  меньше порога — удаляются самые старые вложения (вместе с их сообщениями).
- **Ретеншн** (`UPLOAD_RETENTION_DAYS`): сообщения и файлы старше срока удаляются кроном.

> Безопасность: chunked-путь принимает любой тип файла (нужно для произвольных больших
> файлов). Файлы лежат в `storage/app/private` (не в вебруте) и раздаются только через
> подписанный URL; не-картинки/не-медиа отдаются с `Content-Disposition: attachment`
> (скачивание, без рендера), поэтому HTML/SVG не выполняются.


## Атомарность и повторные запросы

После обновления выполните `php artisan migrate`: у `upload_sessions` появляется
`message_id`. Успешный `complete` сохраняет сессию как квитанцию до истечения
`uploads.session_ttl_hours`; повтор возвращает тот же ID сообщения. Если сообщение
уже удалено, повтор получает 410 и не создаёт его заново. После очистки квитанции
повтор получает 404. Дописывание завершённой загрузки возвращает 409.

Незавершённые сессии резервируют `total_size` из квоты. Обычные вложения учитывают
этот резерв. Создание резерва и финализация сериализуются блокировкой строки
пользователя в БД. Очистка просроченных сессий освобождает резерв.

На завершении повторно проверяются права на чат. Блокировка строки сессии защищает
запись чанков, финализацию и очистку; cache lock позволяет быстро вернуть 409 при
занятой сессии. При повторе чанка незакоммиченный хвост файла обрезается до
`received_size`.

Финализация сохраняет исходный временный файл до коммита сообщения, вложения и
квитанции. Назначение файла детерминировано ID сессии: после сбоя повтор заменит
его, не создавая новые файлы. Незавершённые назначения убирает `attachments:prune`.
Для большого файла во время финализации нужно место для исходника и его копии.
События вложений отправляются после коммита; это не гарантирует доставку при
аварийном завершении процесса после коммита — для такой гарантии нужен outbox.
